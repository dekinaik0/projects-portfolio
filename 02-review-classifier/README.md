# Классификация отзывов: baseline-модель и оценка качества

Пайплайн текстовой классификации: размеченный вручную датасет → обучение модели → замер качества по классам с разбором ошибок.

Всё работает офлайн: внешние API, ключи и платные сервисы не требуются.

## Задача

Отзывы покупателей интернет-магазина раскладываются по двум осям:

- **Категория** — доставка, качество, цена, поддержка
- **Тональность** — положительный, отрицательный, нейтральный

Главный вопрос проекта не «работает ли классификация», а **насколько ей можно доверять**: на каких классах модель проседает, что она путает между собой и какие отзывы стоит отправлять на ручную проверку.

## Стек

Python 3, scikit-learn, pandas, matplotlib.

## Структура

| Файл | Назначение |
|---|---|
| `reviews.csv` | 180 отзывов с эталонной ручной разметкой |
| `train.py` | TF-IDF + LinearSVC, кросс-валидация, запись `predictions.csv` |
| `evaluate.py` | accuracy, precision, recall, F1 по классам, матрицы ошибок |

## Запуск

```bash
pip install -r requirements.txt
python train.py
python evaluate.py
```

## Как устроено

**1. Эталон.** `reviews.csv` размечен вручную — ground truth, относительно которого меряется всё остальное.

**2. Признаки.** Тексты векторизуются двумя TF-IDF одновременно: по символьным n-граммам (3–5) и по словам с биграммами. Символьные n-граммы важны для русского языка — они устойчивы к падежам и окончаниям, где словарный подход видит «доставка» и «доставки» как разные признаки.

**3. Модель.** LinearSVC — линейный классификатор, который хорошо работает на разреженных TF-IDF-признаках и небольших выборках.

**4. Кросс-валидация.** Датасет маленький, поэтому единственное разбиение на train/test дало бы случайный результат. Вместо этого используется `cross_val_predict` на 5 фолдах: каждый отзыв предсказывается моделью, которая его не видела при обучении, и оценка считается по всему датасету сразу.

**5. Оценка.** По каждому классу считаются:

- **precision** — из отнесённых к классу, сколько отнесены верно
- **recall** — из всех отзывов класса, сколько модель нашла
- **F1** — их гармоническое среднее
- **support** — сколько таких отзывов в эталоне

Матрицы ошибок показывают не только количество ошибок, но и какие классы модель путает между собой. Все расхождения выгружаются в `errors.csv`.

## Результаты

| Задача | Accuracy |
|---|---|
| Категория | 0.74 |
| Тональность | 0.62 |

Категория определяется заметно точнее тональности, и это ожидаемо: категория опознаётся по лексике («курьер», «промокод», «оператор»), а тональность требует понимания контекста, которого у мешка слов нет.

Характерные ошибки по тональности:

- **Отрицание не улавливается.** «Ничего не повредилось» содержит негативные по отдельности слова, но смысл положительный.
- **Смешанные отзывы.** «Привезли вовремя, но с царапиной» — разметка на три класса тут спорна сама по себе.
- **Нейтральный класс размыт.** Он реже встречается и хуже отделяется от полюсов, что видно по его метрикам.

Практический вывод: категоризацию можно автоматизировать, а тональность на такой модели — только как черновой фильтр с ручной проверкой спорных случаев.

## Возможные доработки

- Больше данных: 180 отзывов мало, качество упирается в размер выборки
- Лемматизация вместо символьных n-грамм
- Отдельная обработка отрицаний для тональности
- Сравнение с LLM-классификацией на том же датасете и замер разницы в качестве и стоимости
